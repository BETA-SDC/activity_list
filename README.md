# 西湖大学β书院活动中心：数据维护说明

该网站会自动读取 `data/活动表.json` 和 `data/任务分工` 文件夹下的分工文件，向内部成员展示项目计划与分工。
网站包含三个页面：
- Activities：查看全部活动，可按“状态”或“活动类型”分列；状态为“已分工”的活动会显示分工明细。
- Calendar：只展示已填写具体日期（D）的活动。
- Contribution：用堆叠柱状图统计每位成员的总负责人次数和分工负责人次数。

这个网站会自动读取项目里的两个数据来源：

- `data/活动表.json`
- `data/任务分工` 文件夹下的分工文件，优先读取 `data/任务分工/index.json`

页面代码已经拆成三个静态页面和两个共享静态文件：

- `activities.html`
- `calendar.html`
- `contribution.html`
- `index.html`（跳转入口）
- `assets/css/styles.css`
- `assets/js/app.js`

请所有同学在改动文件前先阅读下面的格式要求，避免页面读取失败或显示异常。

## 一、基本规则

1. 所有 JSON 文件都必须保存为 **UTF-8 编码**。
2. JSON 中只能使用 **英文双引号**，不能使用中文引号、单引号或注释。
3. 对象或数组的最后一个元素后面 **不要加逗号**。
4. 所有字段名必须和模板完全一致，包括括号、大小写和空格。
5. 字段值没有内容时，请保留字段并填写空字符串 `""`，不要直接删掉字段。
6. 新增字段不会被页面自动显示；如果确实需要新增字段，请先和网站维护人员确认。
7. 修改文件后，回到页面点击右上角的“刷新数据”，或刷新浏览器。GitHub Pages 有时会缓存旧文件，建议使用 `Ctrl + F5` 强制刷新。

推荐使用 VS Code、Sublime Text、在线 JSON 校验工具等编辑 JSON。不要直接用 Excel 另存为 JSON，容易产生编码或格式问题。

## 二、`活动表.json` 格式模板

文件位置：`data/活动表.json`。

每个活动是一个对象，整体是一个数组。

```json
[
  {
    (上一个活动，略)
  },
  {
    "代号": "P*",
    "活动名称": "示例活动名称",
    "状态": "已分工/待分工",
    "详情": "这里填写活动的简要说明，没有内容时填写空字符串",
    "活动类型": "学术活动/日常活动/校外活动/……",
    "总负责人": "张三",
    "预计月份(Y)": "9",
    "预计日期(D)": "9",
    "开始时间(H)": "14:00",
    "地点": "H4-121"
  }
]
```

字段说明：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `代号` | 必填 | 活动唯一编号，例如 `P1`、`P2`。需要和分工文件中的代号一致 |
| `活动名称` | 建议填写 | 活动名称 |
| `状态` | 必填 | 填写“已分工”时，页面会自动展示对应分工明细 |
| `详情` | 可空 | 活动简介，没有则写 `""` |
| `活动类型` | 必填 | 例如“学术活动”“日常活动”“出校活动”等等 |
| `总负责人` | 可空 | 活动的总负责人姓名。Contribution 页面会统计这个字段 |
| `预计月份(Y)` | 可空 | 只填写月份数字，例如 `9`、`10`。不要填年份 |
| `预计日期(D)` | 可空 | 只填写日期数字，例如 `9`、`23`。Calendar 页面只显示这个字段不为空的活动 |
| `开始时间(H)` | 可空 | 例如 `19:00`，没有则写 `""` |
| `地点` | 可空 | 活动地点，没有则写 `""` |

## 三、`任务分工` 文件格式模板

文件位置：`data/任务分工` 文件夹。

建议先在 `data/任务分工/index.json` 中列出需要加载的文件，再配合连续编号管理：

```text
任务分工-P1.json
任务分工-P2.json
任务分工-P3.json
```

每个分工文件都建议使用数组，方便一个活动记录多条分工，也便于后续统一校验。

```json
[
  {
    "代号": "P1",
    "活动名称": "示例活动名称",
    "分工": "物资采买",
    "负责人": "李四",
    "预计开始时间": "2026/9/1",
    "预计结束时间": "2026/9/6"
  },
  {
    "代号": "P1",
    "活动名称": "示例活动名称",
    "分工": "主持现场",
    "负责人": "王五",
    "预计开始时间": "",
    "预计结束时间": ""
  }
]
```

字段说明：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `代号` | 必填 | 必须和 `data/活动表.json` 中对应活动的代号一致 |
| `活动名称` | 建议填写 | 对应活动名称，方便人工核对 |
| `分工` | 必填 | 具体分工内容 |
| `负责人` | 建议填写 | 负责这项分工的同学姓名。Contribution 页面会统计这个字段 |
| `预计开始时间` | 可空 | 例如 `2026/9/1`，没有则写 `""` |
| `预计结束时间` | 可空 | 例如 `2026/9/6`，没有则写 `""` |

## 四、后续维护注意事项

### 1. 代号要保持一致

`data/活动表.json` 中的“代号”必须和 `data/任务分工` 文件中的“代号”一致。例如活动是 `P2`，分工文件里也要写 `"代号": "P2"`，否则“已分工”状态无法自动匹配分工明细。

### 2. 用清单文件管理分工文件

如果存在 `data/任务分工/index.json`，网站会优先按清单读取，适合长期维护和不连续编号的情况。

推荐写法：

```json
{
  "files": [
    "任务分工-P1.json",
    "任务分工-P2.json",
    "任务分工-P3.json"
  ]
}
```

如果没有清单文件，网站仍会从 `data/任务分工/任务分工-P1.json` 开始自动读取，连续两次找不到文件时停止。

### 3. 三个页面的读取逻辑

- Activities：显示所有活动，可以按“状态”或“活动类型”分列。
- Calendar：只显示 `预计日期(D)` 不为空的活动。
- Contribution：统计 `data/活动表.json` 中的总负责人次数（绿色），以及 `data/任务分工` 文件中的分工负责人次数（蓝色）。

### 4. 更新后要检查

每次修改 JSON 后，请至少打开三个页面检查一次，确认活动数量、日历日期、分工明细和 Contribution 柱状图都符合预期。

## 五、长期维护建议

1. 新活动优先追加到 `data/活动表.json`，再同步补分工文件和清单。
2. 分工文件尽量一活动一文件，文件内部统一用数组。
3. 保持 `代号` 唯一且稳定，后续改名称不要改代号。
4. 尽量把日期写成统一格式，便于后续做排序、筛选和校验。
5. 如果经常多人协作修改，建议在提交前先做一次 JSON 校验，再刷新页面确认展示正常。
